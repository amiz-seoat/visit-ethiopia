# Environment variables

**Rules**
- Never commit real values.
- `backend/config.env`, `frontend/.env` and `frontend/.env.local` are git-ignored.
- In production the backend ignores `config.env` and reads only the host's environment (Render → Environment).
- Only `VITE_*` variables reach the browser bundle. Never put a secret in a `VITE_*` variable.
- `render.yaml` holds the non-secret values. Secrets are marked `sync: false`, so you enter them once in the Render dashboard and they are never stored in git.

Legend: 🔒 = secret (dashboard only), ✅ = set in `render.yaml` or committed, 👤 = you must set it.

## Backend (Render service `visit-ethiopia-api`)

### Core

| Variable | Prod value | Notes |
|---|---|---|
| `NODE_ENV` | ✅ `production` | Switches on: production error responses, secure cookies, strict CORS, rate limits, and config validation. |
| `NODE_VERSION` | ✅ `22` | Render build runtime. |
| `PORT` | set by Render | Defaults to 3000 locally if unset. |
| `DATABASE_MODE` | ✅ `prisma` | `prisma` means PostgreSQL. `mongo` is the legacy path only. |
| `CATALOG_DB` | ✅ `prisma` | Public catalog reads from PostgreSQL. |
| `SKIP_MONGO` | ✅ `true` | Never connect to MongoDB in production. |
| `DATABASE_URL` | 🔒👤 | Neon **pooled** connection string: the `-pooler` host plus `&pgbouncer=true&connect_timeout=15`. Remove `channel_binding=require`. Runtime queries use it. |
| `DIRECT_URL` | 🔒👤 | Neon **direct** connection string, without the pooler. `prisma migrate deploy` uses it during the build. |
| `ALLOW_START_WITHOUT_DB` | unset | For debugging only: lets the API start when the database is unreachable. |

### Auth

| Variable | Prod value | Notes |
|---|---|---|
| `JWT_SECRET` | 🔒 generated by Render (`generateValue`) | Must be at least 32 characters in production, or the server refuses to start. Rotating it logs out every user. |
| `JWT_EXPIRES_IN` | ✅ `7d` | |
| `JWT_COOKIE_EXPIRES_IN` | ✅ `7` | Days. |
| `RATE_LIMIT_MAX` | optional (600) | Requests per 15 minutes per IP, production only. |
| `AUTH_RATE_LIMIT_MAX` | optional (30) | Login, signup and password-reset requests per 15 minutes per IP. |

### URLs and CORS

| Variable | Prod value | Notes |
|---|---|---|
| `FRONTEND_URL` | ✅ `https://visit-ethiopia-rw9b.vercel.app` | Required in production. Used as the CORS origin, the Chapa return URL and in email links. No trailing slash. |
| `CORS_ALLOWED_ORIGINS` | ✅ `https://visit-ethiopia-web.onrender.com` | Extra origins, comma-separated. |
| `PUBLIC_BACKEND_URL` | ✅ from Render service URL | Public API origin for the Chapa callback URL and verification links. |
| `BACKEND_URL` / `PROD_BACKEND_URL` | ✅ / legacy | Fallbacks for `PUBLIC_BACKEND_URL`. |

### Payments

| Variable | Prod value | Notes |
|---|---|---|
| `PAYMENT_PROVIDER` | unset | `chapa` or `mock`. If unset: `chapa` when `CHAPA_SECRET_KEY` is set, otherwise `mock`. |
| `CHAPA_SECRET_KEY` | 🔒👤 optional | Use **test keys first** (`CHASECK_TEST-…`). Live keys (`CHASECK-…`) mean real money and need the owner's explicit approval. |
| `CHAPA_WEBHOOK_SECRET` | 🔒👤 optional | Must match the secret configured in the Chapa dashboard webhook settings. Webhooks with a missing or invalid signature are rejected. |
| `CHAPA_API_BASE` | optional | Defaults to `https://api.chapa.co/v1`. |
| `CHAPA_TIMEOUT_MS` | optional | Timeout for HTTP calls to Chapa. |
| `ALLOW_MOCK_PAYMENTS` | ✅ `true` | Enables the clearly labelled "Confirm demo payment" flow in production for portfolio demos. No money moves. Set it to `false`, or remove it, once Chapa is configured and demo mode is no longer wanted. |
| `MOCK_WEBHOOK_SECRET` | 🔒 generated by Render | Signs mock-provider webhooks. Only relevant when mock payments are allowed. |
| `RECONCILIATION_INTERVAL_MINUTES` | ✅ `5` | Background job: re-verifies pending Chapa checkouts and expires stale holds. `0` disables it. |

If neither Chapa nor mock payments are available, booking creation returns **503** rather than creating bookings that can never be paid.

### Email

**Render free instances block outbound SMTP (ports 25/465/587)**, so Gmail/SMTP times out there. On Render free, use the Brevo HTTPS API, which is free for 300 emails a day. When `BREVO_API_KEY` is set it takes precedence over SMTP.

| Variable | Prod value | Notes |
|---|---|---|
| `BREVO_API_KEY` | 🔒👤 recommended | From Brevo → SMTP & API → API keys. Never commit it. |
| `EMAIL_FROM` | 👤 with Brevo | The sender address. It must be **verified in Brevo** (Senders, Domains & Dedicated IPs → Senders). Falls back to `EMAIL_USER`. |
| `EMAIL_TIMEOUT_MS` | optional | Default 15000. Send timeout for both transports. |
| `EMAIL_USER` | 🔒👤 optional | A Gmail address (with an app password), or the SMTP username. SMTP works locally and on paid instances only. |
| `EMAIL_PASS` | 🔒👤 optional | Gmail **app password** or SMTP password. |
| `EMAIL_HOST` / `EMAIL_PORT` | optional | Generic SMTP. If unset, the Gmail service is used. |
| `EMAIL_FROM` / `EMAIL_FROM_NAME` | optional | Sender. The name defaults to "Visit Ethiopia". |

When email is **not** configured in production, new accounts are auto-verified so signup still works. Password-reset emails can't be sent in that state (see Known Limitations).

### Travel assistant (AI chatbot, optional)

The assistant answers from the curated knowledge base in `backend/data/knowledge/*.json` and live listings. With no key it still works in **search-only mode**, quoting the matching guide section. With a key, a free LLM writes the answer and cites its sources.

| Variable | Prod value | Notes |
|---|---|---|
| `LLM_API_KEY` | 🔒👤 optional | Free **Groq** API key from [console.groq.com/keys](https://console.groq.com/keys). No card is needed. Never commit it; set it only in Render. |
| `LLM_BASE_URL` | optional | Default `https://api.groq.com/openai/v1`. Any OpenAI-compatible endpoint works. For Google Gemini's free tier use `https://generativelanguage.googleapis.com/v1beta/openai` with a Gemini key. |
| `LLM_MODEL` | optional | Default `openai/gpt-oss-120b` (Groq). Use e.g. `gemini-2.5-flash` with Gemini. |
| `LLM_TIMEOUT_MS` | optional | Default 25000. |
| `ASSISTANT_DAILY_LLM_CAP` | optional | Default 900 LLM calls per day (Groq's free tier allows about 1,000). After the cap, answers fall back to search-only mode until midnight UTC. |
| `ASSISTANT_RATE_LIMIT_PER_MIN` | optional | Default 12 chat requests per minute per IP in production. |

| Variable | Notes |
|---|---|
| `DATABASE`, `MONGO_URI`, `MONGOURL` | Legacy MongoDB path (`DATABASE_MODE=mongo`). |

### One-off seed script (run from your machine, not set on Render)

`node scripts/seedDemoMarketplace.js` uses `DATABASE_URL` and `DIRECT_URL` from your shell, plus these optional variables:

| Variable | Effect |
|---|---|
| `ADMIN_EMAIL` + `ADMIN_PASSWORD` (12+ characters) | Creates an admin account. |
| `DEMO_PASSWORD` (10+ characters) | Creates a demo traveler and gives the demo provider a usable login. |

Without these variables the seed creates **no usable logins**. The demo provider gets a random password that is thrown away.

## Frontend (Vercel project `visit-ethiopia-rw9b`, root `frontend`)

| Variable | Value | Notes |
|---|---|---|
| `VITE_API_URL` | ✅ committed in `frontend/.env.production`: `https://visit-ethiopia-api.onrender.com/api/v1` | Public, not a secret. Takes precedence over `VITE_API_BASE_URL`. |
| `VITE_API_BASE_URL` | legacy | Fallback. A stale copy exists in Vercel project settings and points to an old, broken backend. `VITE_API_URL` overrides it, but you should delete it (see Production Deployment → outstanding actions). |
| `VITE_CONTACT_EMAIL` | optional | Public support email shown in the footer and on the Contact page. Hidden when unset. |
| `VITE_CONTACT_PHONE` | optional | Public phone number (e.g. `+251 ...`). Hidden when unset. |
| `VITE_CONTACT_ADDRESS` | optional | Public office address. Hidden when unset. |
| `VITE_SOCIAL_FACEBOOK`, `VITE_SOCIAL_INSTAGRAM`, `VITE_SOCIAL_X` | optional | Full profile URLs. Each icon appears only when its URL is set. |

The contact and social values are shown on the public site, so put only public details in them. No placeholder phone numbers or addresses ship; the Contact page form works without any of them.

A production build (`vite build`) **fails on purpose** if neither variable is set, so a misconfigured deploy can't silently call the wrong API.
